# V05：仅科目二五项的平面草案

历史五项方案：[查看总平面图](layout_v05.png) · [可编辑 SVG](layout_v05.svg)。用户随后提出将原发卡弯及大路改为平面后融合，当前待确认方案已转为 [V06](../layout_proposal_v06/README.md)。下文保留 V05 当时的范围。

按用户最新要求，仅保留倒车入库、侧方停车、曲线行驶、直角转弯、坡道定点停车与起步，每项一处。V04 中的山区发卡弯、低端调头平台、专项回程道路、隧道和雨雾/湿滑段全部退出本方案。未打开、修改或生成 Blender 模型，未改原五项参数文件。

布局建议为 80 × 60 m（4,800 m²），相对原 100 × 75 m（7,500 m²）减少 36%。这是待确认的地块设计值，五项净尺寸没有同比缩小。

路线：西侧入口 → 倒库 → 侧方 → 标准 S 弯 → 直角 → 坡道 → 西侧出口。倒库与侧方之间保持 8 m 同轴直线连接，内含车道宽度渐变；不再通过额外弯路往返两项目。

库位净尺寸、控制线距离、车道净宽、S 弯半径与 135° 圆弧、直角弯外臂 10 m、坡道 10% 恒坡及 R30 竖曲线均沿用确认参数。坡道上下坡总水平投影 57.940 m，平台 6 m，高约 2.298 m。

检查结果见 [planning_checks.json](planning_checks.json)：五项各一处，没有额外项目；所有净铺装轮廓位于地块内；5 cm 栅格检查未见不同考试项目之间的铺装重叠。本轮是平面规划，不表示完成车辆轨迹、路侧设施、坡道土方或认证验收。

布局坐标在 [layout_parameters.json](layout_parameters.json)，制图脚本为 [make_plan.py](make_plan.py)，依赖 NumPy 和 Pillow，不使用 Blender，也不读取发卡弯资产。

V04 保留为历史草案，不再是当前实施依据。下一步仍先由用户确认五项布局，再制作模型。
